## Il vincolo: la finestra di contesto

L’harness carica all’avvio (e a ogni giro del loop) pezzi di testo nella **finestra di contesto** del modello.

Quella finestra **non è infinita**. Ogni riga in `agents.md`, ogni SOP, ogni preferenza “sempre on” ruba spazio al task reale: codice, tool output, ragionamento.

Se il file principale diventa un archivio, l’agente parte già pieno — e lavora peggio.

![Finestra piena vs agents.md come indice snello](img/04-memoria-contesto.png)

## `agents.md`: snello, non enciclopedia

Il file di onboarding (spesso `agents.md` / `CLAUDE.md` / `GEMINI.md`) è la **north star**:

- chi sei / che ruolo hai
- regole dure (cose che non devono mai andare perse)
- **link** a tutto il resto

Non ci metti: tone guide da tre pagine, template lunghi, SOP, transcript, note storiche.

Regola pratica: se non ti serve *a ogni* sessione, **non** stare nel file principale.

## Dividere con link

Struttura tipica — il principale punta, i pezzi vivono altrove:

```text
agents.md              ← indice + regole (sempre caricato)
memory.md              ← preferenze che crescono nel tempo
voice.md               ← tono, pubblico, esempi brevi
context/               ← materiali di riferimento (ICP, product, …)
skills/                ← SOP riusabili (caricate on demand)
```

In `agents.md` bastano righe del tipo:

```markdown
## Contesto
- Voce e tono → [voice.md](voice.md)
- Preferenze persistenti → [memory.md](memory.md)
- Materiali di progetto → [context/](context/)
- Procedure ripetute → [skills/](skills/)
```

L’agente **sa dove guardare**. Non deve aver già mangiato tutto all’avvio.

## Due tipi di “memoria”

| Tipo | Dove | Quando entra in finestra |
|---|---|---|
| **Sempre on** | `agents.md` (poche regole) | Ogni sessione |
| **On demand** | `memory.md`, `context/`, `skills/` | Solo quando il task lo richiede |

`memory.md` è il taccuino vivo: preferenze corrette (“firma così”, “mai usare X”). L’agente lo legge e lo aggiorna; non lo confondi col file principale.

## Disciplina

1. **Cresce `agents.md`?** Sposta il pezzo in un file dedicato e lascia un link.
2. **Serve solo a un workflow?** → `skills/`, non nel boot.
3. **È una preferenza che deve sopravvivere alle sessioni?** → `memory.md`.
4. **È materiale di riferimento lungo?** → `context/`, richiamato quando serve.

Contesto = RAM. File = disco. Il file principale è l’**indice di boot**, non il hard disk intero.
